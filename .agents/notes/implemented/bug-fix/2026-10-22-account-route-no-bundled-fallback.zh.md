# Agent Note: 账号路由在列表不可用时不再提供内置模型

Status: implemented

[English](2026-10-22-account-route-no-bundled-fallback.md) | 中文

## 问题

在账号的 `GET /models` 列表加载成功之前，`deepseek-account` 提供传输层内置的目录——`deepseek-flash` 与 `deepseek-v4-pro`，即上游自带的条目——而一次加载失败会让这个状态保持 `modelsMaxAgeMs`（十分钟）之久。在 Fiwen 部署中，一次短暂的列表故障（例如后端重启）就会显示服务端从未发布过的官方品牌模型，且最长停留十分钟，期间没有任何提示说明发生了替换。

## 决策

- 未持有列表时 `resolveAccountCatalog` 提供空目录。内置条目仍保留在请求解析中，因此已保存会话或 `agent-default-model` 设置引用的模型 id 依旧能解析并送达部署的后端。
- 加载失败超过新增的 `modelsRetryAgeMs`（默认三十秒）后重试，而不是等满 `modelsMaxAgeMs`。尚未持有列表的访问一旦超过该时长会等待这次重试，与首次加载的约定一致，并在同一次访问中返回恢复后的列表。
- 已登录且没有列表时，提供方目录项携带 `model listing unavailable; retrying`；模型页对任何携带错误的目录项都保持账号行可见，让故障可见而不是隐藏提供方。
- 这里收窄了[账号远程模型目录决策](../architecture/2026-09-24-deepseek-account-remote-model-catalog.zh.md)中关于无列表状态的分支；列表获取、版本门控和按凭据隔离均不变。

## 考虑过的替代方案

**保留内置兜底。** 上游内置它是为了让离线启动仍显示可用的 id，但在本部署中这些 id 带着另一个产品的品牌，且模型表里只有 `deepseek-flash` 存在，因此这份显示大多是错的而非有用的。

**持久化上一次成功的列表。** 重启后能恢复真实模型，代价是新增持久化格式及其迁移责任；较短的重试时长加上始终可见的故障提示已经覆盖了常见的短暂故障，不需要新的持久状态。

**只在后台重试。** 能立即返回空状态，但恢复后的模型要等下一次访问才出现；尚未持有列表时等待重试与首次加载约定一致，能在同一次访问中填充选择器。

## 影响

- 列表故障时显示账号提供方的诊断且不显示模型，替代原来的官方条目；列表恢复后，第一次超过 `modelsRetryAgeMs` 的访问即自愈目录。
- 请求解析保留内置知识，未列出的 id 原样透传到后端，因此已有会话和默认模型在故障期间仍能运行，有效性由服务端裁决。
- 模型页的账号行对任何携带错误的目录项保持可见，不再只在其目录有模型时才显示。
